## 0. 一页结论

分母不是「Loon 有多少功能」，而是「广告有多少种」。19 类里 **18 类**有明确手段，1 类（Push）结构上不可达——后者不计入分母，否则任何方案都到不了 100%。

- 当前覆盖 **71%**（39/55）。**这已经是当前手段的真值**——剩下的 16 分全部卡在结构性原因上，不是「还没做」。
- 已经到顶的 **5 类**：开屏广告、H5 / WebView 广告、HTTPDNS / 私有 DoH 绕过、QUIC / HTTP3 绕过、链路劫持 / 运营商插入广告。这些类的上限就是现状，再投入没有档位收益。
- 最大的缺口集中在**同域私有 JSON**：信息流、搜索、直播挂件。它们与内容同构、同域，DNS 与规则层全部失效，只能 MITM + 逐 App 适配。**每多覆盖一个 App 才多一分，不是多写一段代码。**
- 结构上做不到的有 7 件事（**不是 7 类**，是跨类的限制）：Push、DAI 音频、端上缓存素材、传感器交互、正文劫持、证书固定、素材同 CDN。它们散落在多个类里，写进第 5 节，避免以后重复讨论。
- **零证书方案的天花板是 42%**（23/55），与上面的 71% 是两个口径：前者只用 ads 插件（不装 CA、不开 MITM），后者要靠 soda/douyin 的证书层做逐 App 适配。**同一个仓库，两套成本，两个数**——别拿 71% 去要求零证书方案。

> **口径**：所有档位按**纯去广告模式**评价。保奖励模式（`rewardSafe=true`）下，激励视频与激励浏览会被主动放行，那是有意为之，不算覆盖缺口。
>
> 档位：`●●●●` 完全 · `●●●○` 强效 · `●●○○` 部分 · `●○○○` 弱效 · `○○○○` 无效。
> 覆盖率 = Σ权重(现状) / Σ权重(理论上限)；理论上限为「无效」的类不进分母。

## 1. 为什么按「可切断点」分类

按长相分（开屏/信息流/激励）只对用户有意义，对拦截没有指导性——同一个「开屏」，来自 SDK 的可以 DNS 一次拦死，来自自家中台的必须 MITM 剥 JSON，两者的手段和上限完全不同。

所以这里用两层：**族**按「广告在链路的哪一段」分，**类**按用户感知的形态分。每类再标注**协议形态**——这一列决定能不能用 mock：

| 协议形态 | 含义 | 首选手段 |
|---|---|---|
| 标准协议 | VAST / VMAP / OpenRTB / MRAID，格式公开且稳定 | `response.body.mock_file` 返回空清单，比脚本安全 |
| 半标准 | 联盟 SDK 的 JSON，有公开文档但会随版本变 | `[Host]` 黑洞优先；必须改内容时才用脚本 |
| 私有 | 自家业务 JSON，与内容同构同域 | 只能 MITM + 脚本，逐 App 适配 |
| 系统通道 | APNs、厂商推送 | 无手段 |

**展示位**（9 类）—— 用户看得见的那块。拦截目标：让广告位没有东西可渲染。

**触达面**（4 类）—— 不占页面也能到你（推送、H5、音频、大屏）。

**数据面**（3 类）—— 不直接展示，但决定「展示什么、算不算钱」。

**绕路面**（3 类）—— 让上面三层失效的东西：加密 DNS、QUIC、链路劫持。

## 3. 逐类研判

### 展示位（9 类）

#### 1. 开屏广告

**特征**　冷启动 0~5 秒的整屏位。两条来源：联盟 SDK 开屏（穿山甲 `ad.zijieapi.com`、优量汇 `gdt.qq.com`）与自家广告中台（业务域，如 `api.qishui.com/luna/advert/splash/brand/retrieve`）。响应里带素材 URL、曝光上报地址、倒计时与摇一摇参数。

**典型**　抖音 / 小红书 / 知乎 / 微博 / 工具类　·　**协议形态**　半标准

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Host]` | ad.zijieapi.com = 127.0.0.1 | SDK 拿不到填充，直接走「无广告」分支，最彻底 |
| `[Rule]` | DOMAIN-WILDCARD,ads[0-9]-normal*.zijieapi.com,REJECT | 兜住 SDK 的数字分片族，一条顶十几条 |
| `[Script]` | response if ${url} ~= /\/splash\/brand\/retrieve/ then script(sanitize) | 业务域开屏只能剥响应，删掉 brand 对象 |
| `[Rewrite]` | request ... then reject_dict(200) | 上报接口回 `{}`，避免 SDK 因上报失败重试 |

**覆盖**　上限 `strong`（强效）· 现状 `strong`（强效）

**局限**　上次启动预拉的素材会缓存展示一次；摇一摇/扭一扭是传感器事件，Loon 碰不到；无广告时部分 App 仍占 3 秒「跳过」按钮。

#### 2. 信息流广告

**特征**　列表接口把广告当第 N 个 item 返回，与内容**同构**（同 schema）。判据字段：`is_ad`、`ad_info`、`type=ad`、`cell_type`、`creative_id`、`log_extra`。素材走共享 CDN，域名拦不住。

**典型**　抖音 / 小红书 / 微博 / 知乎 / 新闻类　·　**协议形态**　私有

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Script]` | response if ${url} ~= /\/feed\// then script(sanitize) | 遍历数组按字段删除，唯一有效层 |
| `[Host]` | 只拦素材/上报域 | 减少下载量，但列表里的空位还在 |

**覆盖**　上限 `full`（完全）· 现状 `partial`（部分）

**局限**　字段名每个 App 不同；删多了会破分页游标（`cursor`/`has_more` 与广告数耦合）；广告与推荐混在同一 `cards` 数组时，删除会导致索引错位。

**为什么停在这**　结构性：私有 JSON 字段名逐 App 不同，提档 = 多适配一个 App，不是多写一段代码。

#### 3. 激励视频

**特征**　独立 SDK 域，先 `config` 再 `retrieve` 素材，播放完回调 `/reward/verify` 发奖。素材是 m3u8/mp4，走联盟 CDN。

**典型**　游戏 / 工具 / 小说 / 音乐（看广告换权益）　·　**协议形态**　半标准

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Host]` | pangolin.snssdk.com = 127.0.0.1 | 连素材都不下载，最省流量 |
| `[Rule]` | DOMAIN-WILDCARD,ads-*,REJECT | 兜住聚合平台的中转域 |
| `[Script]` | response if ${url} ~= /incentive\/config/ then script(sanitize) | 自营激励位才需要 |

**覆盖**　上限 `full`（完全）· 现状 `strong`（强效）

**局限**　拦了就拿不到奖励——与「保奖励」目标互斥，必须做模式切换；部分 App 检测到「无广告」会把任务置为不可用。

**为什么停在这**　聚合长尾只剩「没有公开请求域证据」的厂商：AdTiming 的 SDK 端点未公开，Smaato 走 smaato.net（已在清单）、Ogury 走 ogury.io（已在清单）。**按品牌名补 .com 会拦到官网却不命中广告请求**——要补只能抓包，抓不到就不补。

#### 4. 插屏 / 半插屏

**特征**　SDK 域，`/interstitial`、`/fullscreen`；预加载后择机弹出，常带 5 秒跳过。与激励视频共用 SDK 连接池，域名往往相同。

**典型**　游戏 / 工具 / 小说　·　**协议形态**　半标准

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Host]` | 与激励视频同一批 SDK 域 | 一次拦截同时干掉插屏与激励 |
| `[Rule]` | DOMAIN-WILDCARD,adserver.*,REJECT | 补充长尾 SDK |

**覆盖**　上限 `full`（完全）· 现状 `strong`（强效）

**局限**　端上预加载的插屏（上次会话缓存）会展示一次；关闭按钮误触是端上逻辑，拦网络改不了。

**为什么停在这**　聚合长尾只剩「没有公开请求域证据」的厂商：AdTiming 的 SDK 端点未公开，Smaato 走 smaato.net（已在清单）、Ogury 走 ogury.io（已在清单）。**按品牌名补 .com 会拦到官网却不命中广告请求**——要补只能抓包，抓不到就不补。

#### 5. Banner / 原生 Banner

**特征**　常驻位，`banner`、`ad_size`、`pos_id` 参数，30~60 秒自动刷新。部分 App 用 WebView 渲染（联盟 JS），部分用原生 View。

**典型**　工具 / 小说 / 资讯 / 免费游戏　·　**协议形态**　半标准

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Host]` | 联盟素材与投放域 | 刷新请求拿不到填充，位空着 |
| `[Rule]` | DOMAIN-WILDCARD,bannerads.*,REJECT | 长尾联盟 |

**覆盖**　上限 `full`（完全）· 现状 `strong`（强效）

**局限**　广告容器仍占高度，会出现空白条；WebView 渲染的 banner 需要额外拦联盟 JS 域。

**为什么停在这**　聚合长尾只剩「没有公开请求域证据」的厂商：AdTiming 的 SDK 端点未公开，Smaato 走 smaato.net（已在清单）、Ogury 走 ogury.io（已在清单）。**按品牌名补 .com 会拦到官网却不命中广告请求**——要补只能抓包，抓不到就不补。

#### 6. 视频贴片（前贴 / 中贴 / 后贴）

**特征**　标准协议：VAST / VMAP 广告清单（XML）+ 素材 CDN。清单域与正片域常常分离（FreeWheel `fwmrm.net`、SpringServe、Tremor），但国内长视频多与业务同域。中贴按时间轴插入，走播放器时间线而不是新请求。

**典型**　爱奇艺 / 腾讯视频 / 优酷 / B 站 / YouTube　·　**协议形态**　标准协议

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Host]` | fwmrm.net / springserve.com 等广告服务器 | 清单拉不到，播放器走无广告分支 |
| `[Rewrite]` | response.body.mock_file 返回空 VAST | 格式固定，比脚本安全；但 mock 不支持 `application/xml` |
| `[Rule]` | URL-REGEX 拦 /\.vmap\|\.vast/ | HTTPS 下需要 MITM 才看得到路径 |

**覆盖**　上限 `partial`（部分）· 现状 `weak`（弱效）

**局限**　**DAI/SSAI**（服务端拼接）把广告混进正片流，客户端拿到的是一条连续流，无法切分；国内长视频的广告接口与业务同域，必须 MITM + 逐 App 定制；`response.body.mock_file` 的 content-type 白名单里没有 `application/xml`，严格校验的播放器会拒绝空清单。

**为什么停在这**　国内长视频的广告接口与业务同域，必须 MITM + 逐 App 定制；DAI/SSAI 把广告混进正片流，客户端拿到的是一条连续流，无法切分。

#### 7. 搜索广告

**特征**　搜索接口响应里混排 `ads`、`promotion`、`commercial` 字段；结果第 1/3/5 位带「广告」角标；联想词带 `ad_type`。与自然结果同构。

**典型**　淘宝 / 京东 / 美团 / 抖音 / 百度　·　**协议形态**　私有

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Script]` | response if ${url} ~= /\/search/ then script(sanitize) | 同域，只有脚本能剥 |
| `[Rule]` | USER-AGENT 拦竞价上报（⚠️ 前提未满足：无 [MITM]） | 只减少回传，不影响展示 |

**覆盖**　上限 `strong`（强效）· 现状 `partial`（部分）

**局限**　与自然结果同构，字段随版本变；剥错会丢搜索结果；「品牌专区」是整块 UI，删数据会留空白。

**为什么停在这**　结构性：搜索结果是同构混排，删哪一条要靠 App 自己的角标字段，无法通用。

#### 8. 直播 / 电商挂件

**特征**　直播间 `room/enter`、`room/init` 返回 `goods`、`promotion`、`popup`、`task`、`floating`；小黄车、讲解卡、红包雨、悬浮挂件。

**典型**　抖音 / 快手 / 淘宝直播 / 小红书　·　**协议形态**　私有

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Script]` | response if ${url} ~= /room\/(enter\|init)/ then script(sanitize) | 删挂件字段，需逐 App 定制 |

**覆盖**　上限 `strong`（强效）· 现状 `none`（无效）

**局限**　电商是核心变现，剥离可能触发风控；`goods` 与直播间初始化强耦合，删了可能直接进不去直播间；红包雨是端上动画。

**为什么停在这**　风控风险：goods 与直播间初始化强耦合，删挂件字段可能直接进不去直播间；红包雨是端上动画，删网络无效。投入产出比不成立。

#### 9. 推广弹窗 / 会员引导

**特征**　`/commerce/upsells`、`/v2/upsell`、`/promotion/popup`；返回弹窗配置、价格档、挽留文案与倒计时。触发点多在看广告、退出、点升级入口时。与会员/支付同域。

**典型**　免费 App / 会员制服务 / 工具类　·　**协议形态**　私有

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Script]` | response if ${url} ~= /commerce\/upsell/ then script(sanitize) | 删掉弹窗配置，UI 不再弹 |
| `[Host]` | 不适用 | 与会员/支付同域，DNS 一拦就断会员页与支付 |

**覆盖**　上限 `strong`（强效）· 现状 `partial`（部分）

**局限**　与会员状态、支付流程同域同接口，剥错会让会员页空白；部分 App 用 WebView 渲染，弹窗内容在页面里；「限时优惠」倒计时是端上逻辑，删网络改不了。

**为什么停在这**　结构性：弹窗配置与会员状态、支付流程同域同接口，每加一个 App 都要重新确认哪些键安全。

### 触达面（4 类）

#### 1. Push 推送广告

**特征**　APNs（443/TCP 或 QUIC，5223 作回退）或厂商通道；payload 内含 `ad`、`promo`、`deeplink`。Loon 看不到 payload——APNs 是系统级双向 TLS 长连接。

**典型**　几乎所有免费 App　·　**协议形态**　系统通道

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `—` | 无 | Loon 无法解密 APNs，也无法只拦「广告类」推送 |

**覆盖**　上限 `none`（无效）· 现状 `none`（无效）

**局限**　**结构不可达**。唯一办法是系统设置关通知，或在 App 内关「营销推送」。拦 push 注册域等于全断推送，不做。

#### 2. H5 / WebView 广告

**特征**　页面里的 GPT/Prebid/联盟 JS：`googlesyndication`、`doubleclick`、`criteo`、`taboola`、`outbrain`；内联 `<ins class="adsbygoogle">`、弹窗、插页、浮层、贴片。

**典型**　所有内嵌网页的 App　·　**协议形态**　标准协议

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Host]` | googlesyndication.com = 127.0.0.1 | 联盟 JS 拉不到，广告位不渲染（覆盖大部分） |
| `[Script]` | response 注入 `display:none` CSS | 需要 MITM 所有站点，证书风险远大于收益 |

**覆盖**　上限 `partial`（部分）· 现状 `partial`（部分）

**局限**　**内联广告位是 HTML 的一部分**，DNS 层拦不到；注入 CSS 要 MITM 任意站点，代价不可接受；WebView 里还可能有 App 自营广告（同域）。

#### 3. 音频广告

**特征**　音频贴片、口播；DAI（动态广告插入）在服务端把广告混进音频流，客户端拿到的是连续音频；或独立广告域返回 mp3/aac。

**典型**　Spotify / 喜马拉雅 / 小宇宙 / 播客　·　**协议形态**　标准协议

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Host]` | 独立音频广告域（少） | 能拦到的只有独立域那一小部分 |

**覆盖**　上限 `weak`（弱效）· 现状 `none`（无效）

**局限**　**DAI 不可切分**；口播是主播内容的一部分；音频 App 的广告素材常与内容同 CDN。

**为什么停在这**　DAI 把广告混进音频流，客户端拿到的是连续音频；口播是主播内容的一部分。结构不可切分。

#### 4. OTT / CTV 大屏广告

**特征**　大屏 App 的开屏 + 贴片 + 屏保；独立 SDK 域较多（`ads.roku.com`、`samsungads.com`、`lgads.tv`）。同一份 ads 插件在 tvOS 生效。

**典型**　Apple TV / Android TV / 智能电视　·　**协议形态**　标准协议

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Host]` | ads.roku.com = 127.0.0.1 | 同一份清单直接复用 |
| `[Rule]` | DOMAIN-WILDCARD | 补长尾大屏 SDK |

**覆盖**　上限 `partial`（部分）· 现状 `weak`（弱效）

**局限**　大屏 App 多用证书固定（MITM 直接失败）；部分走系统播放器，广告由播放器而不是 App 拉取；`#!system` 已含 tvOS，但覆盖面小于移动端。

**为什么停在这**　国内大屏广告域与播控同域，零证书无法只拦广告；证书固定又让 MITM 大面积失败。

### 数据面（3 类）

#### 1. 投放配置 / 素材预拉取

**特征**　`/ads/config`、`/advert/retrieve`、`/sdk/config`；返回广告位开关、频次上限、素材 URL 列表。是「后面所有展示」的总闸。

**典型**　所有带广告 SDK 的 App　·　**协议形态**　半标准

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Script]` | response 清空 ads 数组 | 总闸关掉，后续展示自然没有 |
| `[Rewrite]` | then reject_dict(200) | 更轻，但 SDK 可能按间隔重拉 |

**覆盖**　上限 `full`（完全）· 现状 `strong`（强效）

**局限**　返回空后 SDK 可能按固定间隔重拉（要有节奏地返回空，而不是断开）；部分 App 把 config 与会员状态耦合，清空会误判。

**为什么停在这**　最小合法包络必须改响应体，只有 MITM 能做；零证书插件只能拦域，不能改包。

#### 2. 曝光 / 点击上报

**特征**　`/report`、`/track`、`/impression`、`/click`、`/log`；GET 带 base64 参数或 POST protobuf；fire-and-forget，失败会进本地队列重试。

**典型**　所有带广告的 App　·　**协议形态**　私有

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Rule]` | URL-REGEX,...,REJECT-DICT | 回 200 + `{}`，SDK 认为已落库，清空重试队列 |
| `[Rewrite]` | then reject_dict(200) | 同 URL 更精确的请求层版本 |
| `[Rule]` | REJECT-DROP | 防重试风暴；代价是首次超时略慢 |

**覆盖**　上限 `full`（完全）· 现状 `strong`（强效）

**局限**　拦上报不改变已展示的广告；价值在省电/省流量/降重试，不在「少看广告」；误拦业务埋点会让 App 统计异常。

**为什么停在这**　[Rule] 的 URL-REGEX 在 HTTPS 下需要 MITM 才取得到路径；零证书只能靠域名，看不到 /impression。

#### 3. 归因 / 画像 / 竞价

**特征**　MMP（AppsFlyer / Adjust / Kochava / Singular）、设备指纹、bidding（`/bid`、`/auction`、`/openrtb`）。

**典型**　所有投放过广告的 App　·　**协议形态**　标准协议

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Host]` | 可选组，默认注释 | 会断安装归因与渠道 ROI，只能按需开 |

**覆盖**　上限 `partial`（部分）· 现状 `weak`（弱效）

**局限**　拦归因会断安装归因/渠道 ROI；bidding 被拦只是让瀑布流跳到下一个源，广告仍会出现——它影响的是 eCPM，不是「有没有广告」。

**为什么停在这**　机制不可达：Loon 的 [Argument] 只作用于 [Script]/[Rewrite] 的 enable，管不到 [Host] 与静态 [Rule]（仓库在 soda.plugin 第 57 行已记录该结论）。要让用户能开关，只能拆成独立插件，与单插件 All-in-One 冲突。

### 绕路面（3 类）

#### 1. HTTPDNS / 私有 DoH 绕过

**特征**　`/d`、`/resolve`、`/squery`、`httpdns` 域名；绕过系统 DNS 直接拿 IP，让 `[Host]` 完全失效。

**典型**　抖音 / 快手 / B 站 / 美团 / 各大厂　·　**协议形态**　半标准

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Rule]` | DOMAIN-KEYWORD,httpdns,REJECT-DROP | 未知域兜底，丢包避免重试风暴 |
| `[Rule]` | USER-AGENT,httpdns*,REJECT（⚠️ 前提未满足） | UA 特征兜底：UA 是请求头，无 [MITM] 时看不到 |
| `[Host]` | 已知 HTTPDNS 端点 = 127.0.0.1 | 最精确 |

**覆盖**　上限 `full`（完全）· 现状 `full`（完全）

**局限**　IP 直连的 HTTPDNS 需要 IP-CIDR（默认注释，因为接入点 IP 会变）；拦太狠会让没有回退逻辑的 App 直接断网。

#### 2. QUIC / HTTP3 绕过

**特征**　UDP 443，加密传输，规则层看不到 SNI 之后的路径；`[MITM]` 对 QUIC 无效，脚本根本不执行。

**典型**　Google 系 / 字节系 / 部分大厂　·　**协议形态**　标准协议

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[Rule]` | PROTOCOL,QUIC,REJECT | 强制回退 TCP，MITM 才有机会介入 |

**覆盖**　上限 `full`（完全）· 现状 `full`（完全）

**局限**　回退增加首屏 RTT；部分 App 在 QUIC 失败后会短暂重试，产生额外请求。

#### 3. 链路劫持 / 运营商插入广告

**特征**　HTTP 明文响应被中间设备插入 `<script>`；DNS 被劫持到广告落地页；常见于公共 Wi-Fi 与部分运营商。

**典型**　所有走明文的场景　·　**协议形态**　私有

| 层 | 规则思路 | 买到了什么 |
|---|---|---|
| `[General]` | doh-server = https://223.5.5.5/dns-query | 从源头防 DNS 劫持 |
| `[Rule]` | DEST-PORT,853,REJECT | 阻断自带 DoT 绕过 |

**覆盖**　上限 `partial`（部分）· 现状 `partial`（部分）

**局限**　**已插入的 HTML 正文无法剥离**——除非 MITM 全站 + 正则替换，风险极高；只能靠 HTTPS + DoH 让插入点变少。

## 4. 按层归因：谁在承担覆盖率

| 层 | 涉及类数（含补充） | 说明 |
|---|---:|---|
| `[Rule]` | 13 | 补 `[Host]` 表达不了的通配与特征（`DOMAIN-WILDCARD`、`URL-REGEX`、`PROTOCOL`）。 |
| `[Host]` | 12 | 独立广告域的主力。零证书、HTTPS/QUIC 通吃，是性价比最高的一层。 |
| `[Script]` | 8 | 同域私有 JSON 的唯一解。必须 MITM，且要处理压缩与包络。 |
| `[Rewrite]` | 4 | 轻量替代：能 `reject_dict` 就不写脚本，能 mock 就不写正则。 |
| `[General]` | 1 | 只管 DNS 防泄漏，不直接拦广告。 |

结论：**`[Rule]` 参与的类最多（13 类），但它只能覆盖「域名可分离」的那一半**。剩下的一半压在 `[Script]` 上，而脚本必须逐 App 写——这就是覆盖率的边际成本为什么在上升。一个反直觉的推论：**域名清单的价值在下降，App 适配的价值在上升**，但前者的边际成本几乎为零，后者每加一个 App 都要重新读一遍它的 JSON。

按协议形态看：

| 协议形态 | 当前覆盖 | 为什么是这个数 |
|---|---:|---|
| 标准协议 | 69% | 上限被「素材与内容同 CDN」「服务端拼接」压住，多数只能到 `partial`；能拿的分基本拿到了。 |
| 半标准 | 83% | DNS 黑洞对联盟 SDK 最有效，已接近该形态的天花板；剩下的差距是聚合平台长尾。 |
| 私有 | 58% | 只能 MITM + 逐 App 适配。分子取决于「做了几个 App」，分母是「所有带信息流的 App」——这是当前最贵的一段。 |
| 系统通道 | — | Loon 碰不到，理论上限为「无效」，不进分母。 |

标准协议类的上限普遍只有 `partial`/`weak`——因为标准协议解决的是「广告怎么描述」，不解决「素材和内容同 CDN」；私有类的上限反而更高（`full`/`strong`），因为一旦 MITM 进去，字段是可以删干净的。**这说明「协议越标准越好拦」是个错觉：好拦的不是协议，是域名。**

## 5. 结构不可达清单

下面这些不是「还没做」，是「用 Loon 做不了」。写清楚是为了不再重复投入：

| 做不到的事 | 为什么 | 替代方案 |
|---|---|---|
| 拦 Push 里的广告 | APNs 是系统级双向 TLS 长连接，Loon 看不到 payload | 系统设置关通知 / App 内关营销推送 |
| 切分 DAI 音频广告 | 广告在服务端混进音频流，客户端拿到的是连续流 | 无 |
| 去掉端上已缓存的素材 | 上次会话预拉，本次展示不产生网络请求 | 清 App 缓存 / 重装 |
| 关掉摇一摇 / 扭一扭 | 传感器事件，不经网络 | 无 |
| 剥已插入的 HTML 正文 | 中间设备插入的 `<script>` 已在明文正文里 | 强制 HTTPS + DoH，从源头减少 |
| 绕过证书固定的 App | MITM 握手直接失败，脚本不执行 | 只用 DNS 层（`[Host]`/`[Rule]`） |
| 按域名区分贴片素材 | 广告与正片同 CDN 同签名 | 只能拦广告清单（VAST/VMAP）域 |

## 6. 三层递进方案

覆盖率不是一次性买断的，它按「证书成本」分三层。每层的边际收益递减：

| 层 | 证书 | 能覆盖的类 | 当前覆盖 | 代价 |
|---|---|---|---|---|
| L1 域名层 | 不需要 | 8 类（纯独立域：联盟展示位 + 绕路面） | 78%（18/23） | 零；HTTPS/QUIC 通吃 |
| L2 内容层 | 需要 MITM | 10 类（含同域 JSON 或需改内容） | 只有 2 个 App 做了定制 | 证书 + 逐 App 适配 + 压缩/包络处理 |
| L3 端上 | 不需要 | Push、传感器、端上缓存、悬浮窗 | 不可达 | 只能靠系统设置或 App 内开关 |

两层可叠加（一类广告常常同时用 `[Host]` 拦素材、用 `[Script]` 剥列表），所以上面的类数相加大于 18。

**提升覆盖率的正确顺序**：先把 L1 的域名清单补全（成本最低、收益线性），再对「高频且同域」的少数 App 做 L2 定制（成本高、但每做一个就多一类），最后承认 L3 不可达。反过来做——先堆脚本再补域名——会得到一堆「只在某个版本生效」的规则。

## 7. 差额去哪了：按「谁挡住了」分四组

上一轮这一节叫「下一步清单」，把 16 分的差额全部当成待办列出来，算出一个「做完可到 90%」的数字。**那个数字是假的**：差额里大部分不是「还没做」，而是「做不了」——两类混在一起算，等于把许愿当计划。

这一版把挡路的东西分开：

| 挡路的是 | 判据 | 能不能解 |
|---|---|---|
| 这类广告自己的上限 | `现状 == 上限` | 不能，已经用尽 Loon 能力 |
| 成本（要再加一个 App） | `现状 < 上限` 且有 `blocked` | 能，但要抓包读新 App 的 JSON |
| Loon 的机制 | `现状 < 上限` 且有 `blocked`，且理由是机制 | 不能，除非改插件形态 |
| 物理不可达 | `上限 == 无效` | 不能，不计入分母 |

**A. 还有活干（0 类）**

无。当前 39/55 已是这些手段能达到的全部；再涨只能靠 C 组里「多适配一个 App」那几条——那不是代码问题。

**B. 已到顶（这类广告用尽 Loon 能力，再投入没有档位收益）**

- **开屏广告**：上限就是 `strong`。
- **H5 / WebView 广告**：上限就是 `partial`。
- **HTTPDNS / 私有 DoH 绕过**：上限就是 `full`。
- **QUIC / HTTP3 绕过**：上限就是 `full`。
- **链路劫持 / 运营商插入广告**：上限就是 `partial`。

**C. 停在原地的 13 类：为什么不再涨**

这一组是这一版的重点。它们的上限还没到，但**每一步都要额外付成本**，所以停在当前位置——理由必须写出来，否则下一个人会重新讨论一遍。

- **信息流广告**（`partial` → 上限 `full`）：结构性：私有 JSON 字段名逐 App 不同，提档 = 多适配一个 App，不是多写一段代码。
- **激励视频**（`strong` → 上限 `full`）：聚合长尾只剩「没有公开请求域证据」的厂商：AdTiming 的 SDK 端点未公开，Smaato 走 smaato.net（已在清单）、Ogury 走 ogury.io（已在清单）。**按品牌名补 .com 会拦到官网却不命中广告请求**——要补只能抓包，抓不到就不补。
- **插屏 / 半插屏**（`strong` → 上限 `full`）：聚合长尾只剩「没有公开请求域证据」的厂商：AdTiming 的 SDK 端点未公开，Smaato 走 smaato.net（已在清单）、Ogury 走 ogury.io（已在清单）。**按品牌名补 .com 会拦到官网却不命中广告请求**——要补只能抓包，抓不到就不补。
- **Banner / 原生 Banner**（`strong` → 上限 `full`）：聚合长尾只剩「没有公开请求域证据」的厂商：AdTiming 的 SDK 端点未公开，Smaato 走 smaato.net（已在清单）、Ogury 走 ogury.io（已在清单）。**按品牌名补 .com 会拦到官网却不命中广告请求**——要补只能抓包，抓不到就不补。
- **视频贴片（前贴 / 中贴 / 后贴）**（`weak` → 上限 `partial`）：国内长视频的广告接口与业务同域，必须 MITM + 逐 App 定制；DAI/SSAI 把广告混进正片流，客户端拿到的是一条连续流，无法切分。
- **搜索广告**（`partial` → 上限 `strong`）：结构性：搜索结果是同构混排，删哪一条要靠 App 自己的角标字段，无法通用。
- **直播 / 电商挂件**（`none` → 上限 `strong`）：风控风险：goods 与直播间初始化强耦合，删挂件字段可能直接进不去直播间；红包雨是端上动画，删网络无效。投入产出比不成立。
- **推广弹窗 / 会员引导**（`partial` → 上限 `strong`）：结构性：弹窗配置与会员状态、支付流程同域同接口，每加一个 App 都要重新确认哪些键安全。
- **音频广告**（`none` → 上限 `weak`）：DAI 把广告混进音频流，客户端拿到的是连续音频；口播是主播内容的一部分。结构不可切分。
- **OTT / CTV 大屏广告**（`weak` → 上限 `partial`）：国内大屏广告域与播控同域，零证书无法只拦广告；证书固定又让 MITM 大面积失败。
- **投放配置 / 素材预拉取**（`strong` → 上限 `full`）：最小合法包络必须改响应体，只有 MITM 能做；零证书插件只能拦域，不能改包。
- **曝光 / 点击上报**（`strong` → 上限 `full`）：[Rule] 的 URL-REGEX 在 HTTPS 下需要 MITM 才取得到路径；零证书只能靠域名，看不到 /impression。
- **归因 / 画像 / 竞价**（`weak` → 上限 `partial`）：机制不可达：Loon 的 [Argument] 只作用于 [Script]/[Rewrite] 的 enable，管不到 [Host] 与静态 [Rule]（仓库在 soda.plugin 第 57 行已记录该结论）。要让用户能开关，只能拆成独立插件，与单插件 All-in-One 冲突。

**D. 结构不可达（不计入分母）**

- **Push 推送广告**：**结构不可达**。

**需真机取证（改代码前先确认）**

- `response.body.mock_file` 返回空 VAST 时，播放器是否接受 `text` 而不是 `application/xml`。
- 信息流删除 item 后，分页 `cursor` 是否仍然连续（不同 App 行为不同）。
- 证书固定的 App 清单：哪些 App 在 MITM 开启后直接拒绝连接。

## 8. 怎么读这份表

1. **别只看总覆盖率**。它把「DNS 一次拦死」和「脚本逐 App 适配」算成同一个权重，但两者的维护成本差一个数量级。看第 4 节的按层归因。
2. **看「上限」而不是「现状」**。上限是这类广告用尽 Loon 全部能力的天花板；现状低于上限时，先去第 7 节 C 组看有没有 `blocked`——有就说明不是「还没做」，是「做不了」或「成本不划算」。
3. **看「协议形态」**。标准协议类优先想 mock，私有类才想脚本，系统通道类直接跳过。
4. **`--check` 会拦住吹牛**：声明做了但探不到证据、声明没做却探到了、当前档高于上限，三种情况都会失败。
5. **`--check` 还会拦住「承诺了却说不做」**：`next_to > 现状` 时不许写 `blocked`，`现状 < 上限` 且停在原地时必须写 `blocked`。这一条是第七节能成立的原因——**没有它，删掉一行 `next_to` 就能把「做不到」伪装成「没在做」。**

## 附录：六种可复制的写法

下面是「一类广告 × 一层」的最小片段。域名与路径要换成你实际抓到的；标 ⚠️ 的写法**未在真机验证**，先用一个 App 试。

**① 独立广告域 → DNS 黑洞**（零证书，HTTPS/QUIC 通吃）

```ini
ad.zijieapi.com = 127.0.0.1
*.pangolin-sdk-toutiao.com = 127.0.0.1
```

**② 动态子域 → DOMAIN-WILDCARD**（3.5.3(1008)+，`*` 跨点、`[0-9]` 字符类）

```ini
DOMAIN-WILDCARD,ads[0-9]-normal*.zijieapi.com,REJECT
DOMAIN-WILDCARD,adserver.*,REJECT
```

**③ 上报类 → 回 200 + `{}`**（不要回 404，SDK 会重试）

```ini
URL-REGEX,^https?://[^/]+/(?:report|track|impression|click)(?:/|\?|$),REJECT-DICT
```

**④ 清单类 → 空 VAST**（标准协议，格式确定；⚠️ 播放器是否接受 `text` 待真机）

```ini
response if ${url} ~= /[?&](?:vast|vmap)=/ then response.body.mock_file("text", "empty.vast", 200)
```

把 `empty.vast`（内容 `<VAST version="4.0"></VAST>`）放进 Loon 的 Mock 目录。本仓库插件不用 `mock_file`（外部文件违背自包含），这条是给你在主配置里自己试的。

**⑤ 同域 JSON → 只删广告项**（⚠️ jq 语法与 App 字段名需逐个核对；命中后同 URL 的脚本不再执行）

```ini
response if ${url} ~= /\/feed\// then response.json.jq("del(.data.items[] | select(.is_ad == true))")
```

**⑥ 防绕过 → QUIC 回退 + HTTPDNS 拦截**

```ini
AND,((DOMAIN-SUFFIX,ad.zijieapi.com),(PROTOCOL,QUIC)),REJECT
DOMAIN-KEYWORD,httpdns,REJECT-DROP
DEST-PORT,853,REJECT
```

选哪一条，看第 1 节那张「协议形态」表：标准协议优先 ④，半标准优先 ① + ②，私有才用 ⑤。⑥ 是前置条件——不做这层，上面的规则在 QUIC 与 HTTPDNS 面前会整段失效。
