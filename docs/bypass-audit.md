# 旁路审计：拦了 ≠ 拦住

> 本文件由 `tools/bypass-audit.py` 生成，请勿手改。
> 改插件后跑 `python3 tools/bypass-audit.py --write`。

## 0. 一页结论

前三个分母分别数「功能」「广告类型」「规则前提」，
它们都默认了一件事：**广告请求会走到我们的规则面前**。
这一份数的是第四条假设——广告请求有多少条路可以**绕开整个插件**。

- 共枚举 **17** 条旁路。
- **已封死 6 条**：Loon 有手段且已落地，证据在仓库里能探到。
- **部分封死 4 条**：手段落地了，但只覆盖一部分场景。
- **有手段未落地 1 条**：能做但刻意没做，每条都写了为什么。
- **无解 6 条**：Loon 侧没有手段，每条都写了为什么封不了。

封死率 **54.5%**（分母 11 = 已封死 + 部分封死 + 未落地；无解不进分母——判得越认真分数越低，激励就反了）。
加权封死率 **72.7%**（部分封死记 0.5 分）。

**这条审计最重要的一行是「有手段未落地」那一类**：
它不是「做不到」，是「还没做」。第 4 节写清了每条要怎么在真机上证伪，
证伪通过了才能挪进「已封死」——否则就是把愿望当成事实。

## 1. 四种状态

| 状态 | 含义 | `--check` 要求 |
|---|---|---|
| 已封死 `sealed` | Loon 有手段，且已落地 | 证据必须探得到；**不许**写 blocked |
| 部分封死 `partial` | 手段落地，只覆盖部分场景 | 证据必须探得到；**必须**写 blocked |
| 有手段未落地 `open` | 能做但没做 | 证据必须**探不到**；**必须**写 blocked |
| 无解 `na` | Loon 侧没有手段 | **必须**写 blocked |

「证据探不到」对 `sealed` 是错误，对 `open` 是**正确**。
这套互斥关系就是为了防止把「没做」伪装成「做了」——
与 `ad-surface-audit` 的 `blocked` 断言、`rule-effectiveness` 的 waiver 同源。

## 3. 逐条：为什么停在这

### 1. 公网 DoH 走域名 · 已封死

**怎么绕**　App 自带 DoH（`https://dns.google/dns-query`），在 443 上把域名解析做掉，系统 DNS 与 `[Host]` 都碰不到。

**Loon 的手段**　`[Host]` 把已知 DoH 入口域名映射到 127.0.0.1（DNS 阶段生效，不需要解密，QUIC 也一样拦）。

**怎么证伪**　在 Loon 里看这几个域名的解析结果是否为 127.0.0.1；未知 DoH 服务商不在清单内，走 `resolver-ip-direct` 那条路。

### 2. DoT / DoQ 853 端口 · 已封死

**怎么绕**　App 自带 DoT（TCP 853）或 DoQ（UDP 853），绕过 Loon 的 DNS。

**Loon 的手段**　`DEST-PORT,853,REJECT`——端口在连接层可见，不需要域名也不需要解密。

**怎么证伪**　官方 `Rule/port_rule` 页没有限定 TCP/UDP；而 `PROTOCOL` 支持 `UDP` 值（`Rule/protocol_rule`），说明 UDP 连接同样进规则引擎。若真机发现 DoQ 仍能穿透，确定解法是主配置的 `disable-udp-ports = 853`（插件 `[General]` 白名单里没有该键）。

### 3. HTTPDNS 走域名 · 已封死

**怎么绕**　SDK 请求 `xxxhttpdns.xxx.com` 换回广告域的真实 IP，再用 IP 直连，绕开系统 DNS 与 `[Host]` 黑洞。

**Loon 的手段**　`[Host]` 黑洞已知域名 + `DOMAIN-KEYWORD,httpdns,REJECT-DROP` 吃未知域名 + `USER-AGENT` UA 特征兜底。

**怎么证伪**　日志里搜 `httpdns` 关键词规则的命中；若命中为 0 且广告仍在，说明该 SDK 走的是 IP 直连（见 `httpdns-ip`）。

### 4. 长连接 / 私有协议下发广告配置 · 已封死

**怎么绕**　广告配置通过长连接或私有 TCP 协议下发，不走 HTTP，`[MITM]` 与脚本都看不到内容。

**Loon 的手段**　`[Host]` 域名黑洞：连都连不上，长连接也建立不起来——**DNS 层对协议形态免疫**。

**怎么证伪**　这条「已封死」依赖的是 DNS 层主力（1362 条生效黑洞）而不是解密层；若某天把主力改成规则层或脚本层，这条会立刻降级为 partial。

### 5. QUIC / HTTP3 绕过解密 · 已封死

**怎么绕**　广告请求走 UDP 443，`[MITM]` 只处理 TCP，脚本根本不执行。

**Loon 的手段**　按域 `AND,((DOMAIN-SUFFIX,…),(PROTOCOL,QUIC)),REJECT` 逼回 TCP+TLS；**不做**全局 `PROTOCOL,QUIC,REJECT`。

**怎么证伪**　ads 是零证书 DNS 层，`[Host]` 在 DNS 阶段生效，不受 QUIC 影响；只有带 `[MITM]` 的 soda/douyin 需要回退。真机看请求日志里广告域是否出现 HTTP/3。

### 6. Loon 跑在直连模式 · 已封死

**怎么绕**　`running_model = 0` 时 Loon 不走规则、不进 MITM、不跑脚本，插件完全不生效，而界面上只显示「直连」两个字。

**Loon 的手段**　`$config.getConfig()` 读 `running_model`，状态页点名告警并给处置建议。

**怎么证伪**　状态自检按钮里应显示「运行模式 直连（⚠️ 插件不生效）」；看不到就说明脚本没跑（先看上一条 bypass-tun）。

### 7. HTTPDNS 走 IP 直连 · 部分封死

**怎么绕**　SDK 硬编码接入点 IP（如 `203.107.1.x`）直连换成 IP，连接层**没有域名**，`[Host]` / `DOMAIN-KEYWORD` / `URL-REGEX` 全部失效。

**Loon 的手段**　`IP-CIDR`（规则层）与 `[IP Rewrite]`（TUN 阶段，最快）——两者都是可选、默认关闭。

**为什么没封死**　默认关闭：这些 IP 段与云厂商其它业务共用（`IP-CIDR` 一拦就是整段），且火山/阿里官方文档写明接入点是 SDK **动态拉取**的，静态化会随版本失效。要开就得逐版本人工核对，不能常开。

**怎么证伪**　开一组后跑一天：广告是否消失 + App 是否有登录/支付异常；两者都正常才算这组 IP 可留。

### 8. 明文 HTTP 广告与上报 · 部分封死

**怎么绕**　少量广告/上报端点仍是明文 `http://`。

**Loon 的手段**　`URL-REGEX,^http://…`，不需要解密就能匹配完整 URL。

**为什么没封死**　这几条正则锚定 `^http://`，**只吃明文**。同样路径的 HTTPS 端点要 `[MITM]` 才看得到，而 ads 没有 `[MITM]`。技术上有效、实际命中面很窄（见 `docs/rule-effectiveness.md` 第 4 节）。

**怎么证伪**　日志里搜这几条规则的命中数；长期为 0 就该考虑删掉，而不是继续把它当成一层防护。

### 9. 公共解析器 IP 直连（53/443/853 全端口） · 部分封死

**怎么绕**　App 不请求 DoH 域名，直接连 `8.8.8.8:443` 或 `1.1.1.1:853`。此时**域名根本不存在**：`[Host]` 黑洞、`DOMAIN-KEYWORD`、`URL-REGEX` 全废，`DEST-PORT,853` 也只挡端口、挡不住 443 上的 DoH。

**Loon 的手段**　`IP-CIDR` / `IP-CIDR6`——连接层只看 IP，是这条旁路**唯一**能在插件里生效的手段。

**为什么没封死**　默认关闭：用户主配置可能把 8.8.8.8 / 1.1.1.1 当作 `dns-server` / `doh-server`，插件规则一旦命中就会掐断 Loon 自己的解析链（表现是**全网上不了**，比广告回来严重得多）。且 anycast IP 会变。开启前必须逐条核对主配置。

**怎么证伪**　① 主配置 `dns-server` / `doh-server` 里没有清单内任何 IP；② 开启后网络与广告域解析（应为 127.0.0.1）都正常；③ 用 `dns.leak` 类工具确认 App 侧解析确实回到 Loon。

### 10. 广告接口与业务同域（靠路径区分） · 部分封死

**怎么绕**　广告配置走业务域名下的某个路径，只靠域名拦会连业务一起打死。

**Loon 的手段**　`[MITM]` + response 脚本按 URL 正则与字段裁剪（soda/douyin 已落地）。

**为什么没封死**　ads 是零证书 DNS 层，看不到路径，只能整域拦——而整域拦会打死业务。soda/douyin 这类带 `[MITM]` 的插件能按路径处理，但**每多适配一个 App 就要重新抓包确认哪些键安全**（见 `docs/ad-type-strategy.md` 的 blocked 说明）。

**怎么证伪**　新增 App 时先抓包确认广告配置端点与业务端点是否同域；同域才值得加到 `[MITM]`。

### 11. IPv6 / AAAA 旁路 · 有手段未落地

**怎么绕**　`[Host]` 里 1362 条生效黑洞（另有 118 条默认注释）**全部只映射 IPv4**（127.0.0.1）。若 Loon 对命中域名仍放行真实 AAAA 记录，App 走 IPv6 直连就绕过了整个黑洞。

**Loon 的手段**　`[Host]` 的 `ip-mode:ipv4-only` 右值（官方 `DNS/hostmap` 支持 `ipv4-only`/`dual`/`ipv4-preferred`/`ipv6-preferred`）；或主配置 `ipv6-vif = off`（插件能声明，但关的是整个 TUN 的 IPv6）。

**为什么没封死**　**有手段但刻意不落地**。官方 `DNS/hostmap` 只给了 `ip-mode:` **单独使用**的示例，没有给同一域名同时写 `= 127.0.0.1` 与 `= ip-mode:ipv4-only` 的示例。若 Loon 一个域名只认最后一条，补 ip-mode 会**把黑洞覆盖掉**——比不补更糟（广告全回来且排查方向完全错）。在确认「多行共存」之前，不拿 1362 条生效规则（含默认注释共 1480 条）去赌。

**怎么证伪**　① 先用一条无关域名验证共存：`probe.example = 127.0.0.1` 与 `probe.example = ip-mode:ipv4-only` 各写一行，看 A 记录是否仍是 127.0.0.1；② 再单独确认 `probe.example` 的 AAAA 查询返回空还是真实地址——**返回真实地址才说明旁路真的存在**，才值得补。两步都为正，再批量生成 ip-mode 行并接进 lint。

### 12. App 被主配置 bypass-tun 排除 · 无解

**怎么绕**　App 被排除在 TUN 之外，流量完全不进 Loon，规则/MITM/脚本一律不执行。

**Loon 的手段**　无（`bypass-tun` 只在主配置声明；插件声明它就是全局生效，与「只拦广告」无关）。

**为什么没封死**　插件不能也不会去接管 TUN 范围——那是在替用户改全局网络边界，出问题时无法归因。

**怎么证伪**　Loon 的请求日志里完全没有该 App 的任何记录，即为该旁路命中。

### 13. 证书固定导致解密失败 · 无解

**怎么绕**　App 校验证书链，`[MITM]` 握手失败 → response 脚本不执行，响应体净化整条链路失效。

**Loon 的手段**　无。官方 MitM 页只列 `hostname` / `ca-p12` / `ca-passphrase`，没有 `skip-server-cert-verify` 之类的键。

**为什么没封死**　证书固定是 App 侧的信任链校验，代理侧没有官方开关。仓库的做法是把它列为**已知风险并给退路**：受影响时把对应广告域从 `[MITM]` 注释掉，退回域名层拦截（见两个插件头部注释第 2 条）。

**怎么证伪**　开启 `blockAdDomains` 后某个 App 完全打不开/白屏，即为该旁路命中；删掉 `[MITM]` 里对应域可确认。

### 14. 接管前的 DNS 缓存残留 · 无解

**怎么绕**　App 在 Loon 接管之前已解析并缓存了广告域的真实 IP。

**Loon 的手段**　无。插件清不掉 App 进程内的缓存。

**为什么没封死**　缓存属于 App 进程状态，网络层不可见也不可写。

**怎么证伪**　重开 App（不是重开 Loon）后广告是否消失：是 → 只是缓存；否 → 真的漏拦。

### 15. 硬编码 IP + SNI 直连 · 无解

**怎么绕**　SDK 内置广告服务 IP，直接 `https://1.2.3.4/...` 带 SNI 请求，域名不出现在连接层。

**Loon 的手段**　无。`IP-CIDR` 只能逐条枚举，`IP-ASN` 会打死整个云厂商。

**为什么没封死**　广告服务的 IP 是 anycast 且随时变更，逐条枚举必然漏；而广告与正常业务常常同 ASN（`IP-ASN` 一拦就是全站）。这条只能靠广告域的 DNS 层拦，拦不到 IP 直连形态。

**怎么证伪**　抓包看到 `https://<IP>/` 形态且 Host/SNI 是广告域时，才有具体目标可写；没有抓包证据不写 IP 规则（见第七轮「从品牌名推域名」的教训）。

### 16. 本地缓存与素材预拉取 · 无解

**怎么绕**　广告素材与配置在上次联网时已下载到本地，本次渲染不发起任何请求。

**Loon 的手段**　无。网络层拦不到本地渲染。

**为什么没封死**　这是客户端行为，不是网络路径。任何代理工具都对它无效——这也是为什么「拦了域名但广告还出现一次」经常是正常现象，而不是规则失效。

**怎么证伪**　冷启动（清 App 数据）后首次打开是否无广告：是 → 规则有效；否 → 才是真的漏拦。

### 17. 主配置规则盖掉插件规则 · 无解

**怎么绕**　官方 `Rule/` 写明来源优先级 **本地 > 插件 > 订阅**。用户主配置里一条 `DOMAIN-SUFFIX,xxx,DIRECT` 就能让插件的 `REJECT` 永远轮不到。

**Loon 的手段**　无。插件侧没有任何 API 能读取或改写主配置规则。

**为什么没封死**　插件读不到主配置，也无法声明优先级。只能写进 README 的排障段：「广告突然全回来」时第一步就是查主配置有没有指向广告域的 DIRECT/代理规则。

**怎么证伪**　把插件规则原样复制到主配置最前面，若拦截恢复，即为该旁路命中。

## 4. 「有手段但未落地」清单（真机待办）

这一类必须被单独看见：它不是做不到，是**还没验证**。
每条都给了真机动作，做完才能挪进「已封死」。

- **IPv6 / AAAA 旁路**：① 先用一条无关域名验证共存：`probe.example = 127.0.0.1` 与 `probe.example = ip-mode:ipv4-only` 各写一行，看 A 记录是否仍是 127.0.0.1；② 再单独确认 `probe.example` 的 AAAA 查询返回空还是真实地址——**返回真实地址才说明旁路真的存在**，才值得补。两步都为正，再批量生成 ip-mode 行并接进 lint。

## 5. 四个数，四个分母

| 度量 | 分母 | 回答什么 | 当前 |
|---|---|---|---|
| 能力利用率 | Loon 的功能 | 功能用了多少 | 见 `docs/loon-coverage.md` |
| 广告面覆盖率 | 广告的类型 | 广告还剩多少 | 见 `docs/ad-type-strategy.md` |
| 规则有效率 | 已写的规则 | 写了的有多少真会命中 | 见 `docs/rule-effectiveness.md` |
| **路径封死率** | **绕过的路** | **拦了的是不是真拦住** | 本文件 |

四者层层收紧：功能用了 → 广告覆盖了 → 规则生效了 → **但请求还有别的路**。

## 6. 门禁

`--check` 六条断言：

1. 标「已封死」却写了 blocked —— 矛盾。
2. 标「已封死 / 部分封死」但证据探不到 —— 声明与事实不符。
3. 标「部分封死」但没写 blocked —— 剩那部分为什么封不了，必须说。
4. 标「有手段未落地」但没写 blocked —— 为什么不做，必须说。
5. 标「有手段未落地」却探到了证据 —— 状态写错了。
6. `docs/bypass-audit.md` 必须与工具输出一致。
