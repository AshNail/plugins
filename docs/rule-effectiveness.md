# 规则有效率审计：写了 ≠ 生效

> 本文件由 `tools/rule-effectiveness.py` 生成，请勿手改。
> 改插件后跑 `python3 tools/rule-effectiveness.py --write`。

## 0. 一页结论

能力覆盖率回答「Loon 的功能用了多少」，广告面覆盖率回答「广告还剩多少」。
两者都只数**声明**。这一份数**前提**：一条规则写在插件里，
是否具备它命中所需的条件。

- 共审计 **147** 条会依赖前提的配置行，分布在 `[Rule]` / `[Script]` / `[Rewrite]`。
- **前提满足 137 条**（93%）：连接层可见，或插件已声明 `[MITM]`。
- **仅明文 6 条**（4%）：正则锚定 `^http://`，不依赖解密，但也只吃明文 HTTP——现代 App 几乎全 HTTPS，实际命中率很低。
- **存疑 4 条**（3%）：需要 HTTP 报文内容，但插件没有 `[MITM]`。

存疑不等于错，但必须登记。当前 4 条存疑全部已登记 waiver（见第 3 节），每条都写了保留理由与**真机证伪方法**。

## 1. 三种前提

| 前提 | 含义 | 能被谁满足 |
|---|---|---|
| `none` 连接层 | 只看域名 / IP / 端口 / 协议 | 任何插件，无需证书 |
| `plain` 仅明文 | 需要完整 URL 或请求头，但正则锚定了 `^http://` | 明文 HTTP 流量 |
| `mitm` 需解密 | 需要 URL 路径、请求头或响应体 | **必须有 `[MITM]`** |

判定规则：

- `USER-AGENT` 一律 `mitm`——它是 HTTP 请求头。
- `URL-REGEX` 锚定 `^http://` → `plain`；否则 `mitm`。
- `AND` / `OR` / `NOT` 取**内部子规则里最强的那个**（一条 `AND` 里
  掺一个 `USER-AGENT`，整条就需要解密）。
- 其余（域名类、IP 类、端口、协议、进程名）都是 `none`。

## 3. 存疑清单与豁免登记

### `ads.plugin` 的 `USER-AGENT`（4 条）

- `httpdns*`
- `Httpdns*`
- `httpsdns*`
- `Httpsdns*`

**为什么保留**　作为 HTTPDNS 的 UA 特征兜底：域名不含 httpdns 但 UA 含的 SDK，理论上能被这层抓到。保留成本为零——不解密就不会误伤任何明文流量。

**存疑在哪**　ads 插件**没有 [MITM] 段**（它的定位是零证书 DNS 层）。User-Agent 是 HTTP 请求头，未解密的 HTTPS 里看不到；官方 HTTP 规则页只写了「匹配请求 Header 中的 User-Agent」，没有写未解密时是否降级。因此这 4 条很可能命中数为 0。

**怎么证伪**　① 日常使用中打开 Loon 请求日志，搜索这 4 条规则的命中记录；② 若要确证：临时给 ads.plugin 加 `[MITM] hostname = *`，对比加之前/之后的命中数。若从 0 变为 >0，即证明默认配置下它们不生效，届时应当删除或改为把 UA 特征并入域名层。

## 4. 仅明文生效的规则

这些规则锚定了 `^http://`，不需要解密，因此**不是**存疑——
但它们的生效面只有明文 HTTP，而现代 App 的接口几乎全是 HTTPS。
这是一个「技术上有效、实际上罕见」的夹层，值得单独看见，
否则很容易把它和「前提满足」混为一谈。

| 插件 | 段 | 规则 |
|---|---|---|

## 5. 三个数，三个分母

| 度量 | 分母 | 回答什么 | 当前 |
|---|---|---|---|
| 能力利用率 | Loon 的功能 | 功能用了多少 | 见 `docs/loon-coverage.md` |
| 广告面覆盖率 | 广告的类型 | 广告还剩多少 | 见 `docs/ad-type-strategy.md` |
| **规则有效率** | 已写的规则 | **写了的有多少真会命中** | 本文件 |
| 路径封死率 | 绕过的路 | **拦了的是不是真拦住** | 见 `docs/bypass-audit.md` |

前两个数的分子都是「声明」。**声明可以被写错、被架空、被前提卡住**，
所以还需要第三个分母来兜底；而第三个分母默认了「请求会走到规则面前」，
于是还需要第四个。四者不是替代关系，是层层收紧。

## 6. 门禁与自查

`--check` 三条断言：

1. **存疑必须登记**：判定为 `mitm` 前提却没有 `[MITM]` 的规则，必须在本文件的 `WAIVERS` 里写明保留理由与验证方法。
2. **失效 waiver 必须清掉**：登记了但仓库里已无对应存疑规则的，会被报为 stale——避免豁免表越积越多，最后变成新的盲区。
3. **文档不过期**：`docs/rule-effectiveness.md` 必须与工具输出一致。

与 `ad-surface-audit` 的 `blocked` 断言同源：
**允许存疑存在，但禁止存疑沉默。**
